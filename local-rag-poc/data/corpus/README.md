# data/corpus/ — 取り込み対象資料の置き場

このディレクトリに置いたファイルが RAG の検索対象になります（`.pdf` / `.txt` / `.md`。サブディレクトリも再帰的に取り込まれます）。ファイルを置いたら `make ingest`（docker の場合は `docker compose exec app python -m src.ingest`）を実行してください。

このディレクトリの中身は `.gitignore` により **git にコミットされません**（この README と `.gitkeep` を除く）。取り込み資料を誤ってリポジトリの配布経路に乗せないための措置です。

---

## ここに置いてよいもの

以下の**どちらか**に該当するものだけです。

- **公開資料**: 誰でも入手できる形で公開されているもの（例: メーカーが公開している PDF カタログ、官公庁・団体の公開技術資料）
- **本人の学習用資料**: 自分自身が学習のために作成したもの（例: 電験二種の自作学習ノート）

置く前のセルフチェック:

- [ ] このファイルは公開資料、または自分が自分のために作った学習資料か？
- [ ] 業務で入手・作成したファイルではないか？
- [ ] 内容に顧客名・型番・回路定数など、就業先由来の情報が含まれていないか？

## 絶対に置いてはならないもの（最優先ルール・違反したら即中止）

指示文書 §2「絶対禁止事項」の全文を転記します。

> - **現職および過去の就業先の業務文書を一切使用しない。** 設計計算書、仕様書、図面、帳票、社内資料、顧客名・型番・回路定数を含むいかなるファイルも取り込まない。
> - 取り込み対象は `data/corpus/` に配置された **公開資料または本人の学習用資料のみ**。
> - 外部LLM API（Anthropic / OpenAI / Google 等）を**呼ばない**。ネットワークはモデルの初回ダウンロード時のみ使用し、それ以降は**機内モード状態でも動作すること**を要件とする。
> - ライセンス表記が必要なOSS・モデルは `THIRD_PARTY_LICENSES.md` に列挙する。

「取り込んでもローカルだから外部には出ない」は、ここに就業先の文書を置いてよい理由に**なりません**。本PoCは面接で第三者に見せる成果物であり、就業先由来のファイル名・内容が画面や評価結果に一度でも表れた時点でアウトです。迷ったら置かないでください。

## 補足

- 誤って禁止対象のファイルを置いてしまった場合は、そのファイルを削除したうえで `make clean-db` → `make ingest` を実行し、ベクタDB（`data/chroma/`）からも痕跡を消してください（DB はコレクションごと作り直されます）。
- 評価（`eval/golden_set.yaml`）の `expected_sources.file` は、ここに置いた**実ファイル名**と一致させる必要があります。資料を差し替えたら golden_set も更新してください。
